# 学生改密流程与输入可见性

生产基线：`7455f6cd6d5ee26da1ded76e6271ad8fd609c003`。本任务不部署生产，不修改真实学生账号，不包含班级批量管理功能。

## 已授权改动

账户设置的当前密码、新密码、确认新密码各有独立显示/隐藏开关，默认隐藏。按钮有中文可访问名称，可用键盘操作；切换不改输入、不触发提交，保留输入焦点与选区。三个输入有准确的 label、id、name 与 autocomplete；窄屏不溢出。密码不得写入日志、提示或监控。

基线 QA 已复现两个会话同时提交不同密码均报告成功、最终仅保存一个的覆盖缺陷。保存必须以本次已经校验的旧密码版本为条件；若被其他请求更新，则明确返回冲突，不报告保存成功。

## 独立验收

- 在隔离数据库与多个独立合成学生上先测未修改生产基线，再测冻结候选。
- 完整网页流程：登录、通过用户菜单进入账户设置、改密、退出、新密码登录、旧密码拒绝、旧会话失效、同网页改回并登录。
- 合成测试覆盖错误旧密码、新密码不一致、大小写、首尾及中间空格、自动填充语义、快速重复提交和多标签会话。
- 新开关分别控制各字段；鼠标点击保留输入焦点/选区，键盘按键可切换；值保持不变且不产生改密请求。桌面与窄屏实际浏览器验证。
- Chromium 会在 type 切换后延迟重置选区；补偿只能在原输入仍聚焦且值不变时生效，后续按键、鼠标输入或离焦必须取消补偿，不能覆盖用户新操作。
- 反馈附图只在截图副本中清空密码字段（包括显示为文本的密码），不得将其序列化进截图；活页面的字段值、类型与选择保持不变。
- 提交值只做合成值的布尔相等校验，报告不记录密码；不将合成测试通过等同真实账号恢复或断言历史事故的具体输入原因。
- 应用改动执行类型检查、完整 Vitest、改动文件 lint；冻结候选后由独立 QA 用 task_state 绑定 SHA、环境与报告。

历史事故已知保存值与随后口述候选不一致，真实提交字符没有留存。不能凭此指认用户输错或产品保存错误；若发现可复现缺陷，再按证据做最小修复。
